# K2 (durable event log)

`env.<binding>` is the K2 produce binding — a durable, ordered event
stream the worker appends to with `send(records)`. It resolves
`{success: true}` on commit and `{success: false, error: {code,
message, retryable}}` on every failure — the CF K2 contract is
non-throwing; only local argument misuse throws (`TypeError`).

**Status: Partial** — the produce surface works end to end
(batch + per-record limits, base64 wire, typed error envelope).
Consume is not a worker binding — reads ride the platform's
subscription surface.

## Wrangler configuration

```toml
[[k2]]
binding = "K2"
stream  = "events"      # user-side stream name — [A-Za-z0-9_-]{1,256}
# remote = true         # accepted and ignored (local-dev knob)
```

Native `vrt.toml` equivalent — `name -> stream name`:

```toml
[bindings.k2]
K2 = "events"
```

`binding` and `stream` are both required. The wire `streamId` is
server-derived at pack time — first 32 hex chars of
`sha256("vrt-k2:{tenant}:{stream}")` — so a worker can never name an
arbitrary stream; the signed desired snapshot covers the derived id.

## Using it

```js
export default {
  async fetch(req, env) {
    const r = await env.K2.send([
      { content: "hello" },
      { content: new Uint8Array([1, 2, 3]), headers: { tenant: "t1" } },
    ]);
    if (!r.success) {
      // non-throwing: {error:{code,message,retryable}}
      return new Response(r.error.code, { status: r.error.retryable ? 503 : 400 });
    }
    return new Response("ok");
  },
};
```

## Behaviour notes

- `send(records)` resolves — it never rejects on a service failure.
  `{success:true}` on commit, otherwise `{success:false, error:
  {code,message,retryable}}`.
- Local misuse throws `TypeError`: non-array argument, non-object
  record, `content` that is not `string|ArrayBuffer|ArrayBufferView`,
  non-string header values.
- Local validation resolves, not throws: empty batch →
  `INVALID_BATCH`; a record over 1 MiB → `RECORD_TOO_LARGE`; batch
  over 5 MiB → `BATCH_TOO_LARGE`; >64 header entries or a >1 KiB
  header key/value → `INVALID_HEADERS`. These never reach the
  backend.
- String content is UTF-8 encoded; binary content is base64'd by the
  shim. Byte limits count the **encoded** bytes.

## Limits

| Limit | Value |
|---|---|
| Record `content` | 1 MiB |
| Batch total | 5 MiB |
| Header entries per record | 64 |
| Header key / value | 1 KiB each |

## Where it runs

The binding renders as a workerd `wrapped` binding over
`cloudflare-internal:k2` whose inner `fetcher` service binding points
at the `facade-k2` system worker (`vrt-config/src/capnp.rs`,
`facade/facade-k2.ts`). Signed props carry `bindingId` =
`{workerId}~{name}` and `namespaceResourceId` = streamId; the facade
is deny-routed and accepts only `POST /send`.

The facade drains the body bounded, strips user-controllable
`x-vrt-*` / `x-open-compute-*` headers, mints the provider request id,
and forwards to `/internal/bindings/v1/k2/<bindingId>/send` on the
provider socket — the same `BINDING_BACKEND` channel as d1/queue.
The provider maps `bindingId` to the signed `streamId`, validates the
records again (defense in depth), and produces to vrt-sql
`/streams/{id}/produce`. Replies pass through as the non-throwing
`{success,error}` envelope.

## Backends

`vrt-provider`'s `k2` route is a thin authorizer over the same
vrt-sql store that backs d1/queues: `K2Client` posts
`/streams/{streamId}/produce` against the tenant's vrt-sql
downstream. Absent downstream → `BACKEND_UNAVAILABLE` (503,
`retryable: true`). Produce requires the signed `write` grant —
`read`-only bindings get `BINDING_PERMISSION_DENIED`.

## Unsupported keys and error shape

- `[[k2]]` accepts `binding`, `stream`, `remote` only — anything
  else → `VRT_CONFIG_UNSUPPORTED_FIELD` (`k2[i].<key>`).
- Missing/empty `binding` or `stream`, or a stream outside
  `[A-Za-z0-9_-]{1,256}` → `VRT_CONFIG_INVALID`.
- Runtime envelope codes — local validation: `INVALID_BATCH`,
  `INVALID_RECORD`, `RECORD_TOO_LARGE`, `BATCH_TOO_LARGE`,
  `INVALID_HEADERS`; transport: `PROTOCOL_ERROR` (non-JSON backend
  reply), `BACKEND_UNAVAILABLE`; authorization:
  `BINDING_PERMISSION_DENIED`. Backend codes (e.g. `SLOTS_FULL`)
  pass through with their `retryable` flag.

## Known differences from Cloudflare

- **Produce only.** `env.<name>.send()` exists; there is no
  consume/read method on the binding — consumption rides the
  platform's subscription surface, not a worker API.
- **Server-minted streamId.** `stream` is a display name; the routed
  id is the platform's `vrt-k2:` digest — same derivation rule as
  queue/database ids.
- **Single writer group semantics.** Ordering and retention are
  vrt-sql's, not Cloudflare's multi-cell stream guarantees.
